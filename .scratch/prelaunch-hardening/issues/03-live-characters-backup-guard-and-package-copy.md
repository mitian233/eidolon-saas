## 验收项

- [x] 启动时不加载全站角色。运行中的服务经数据库工作线程按账号读取角色，旧测试仍覆盖原有行为。
- [x] 两个 API 实例共用真实 PostgreSQL。A 新建角色后 B 能开始对话并完成文字回合，A 修改后 B 下一回合使用新人设和称呼并能读到新名字，A 删除后 B 返回 404。
- [x] PostgreSQL 的内置备份、后台接口、看板及命令行备份与恢复给出中文说明。看板不把 PostgreSQL 当作备份故障，SQLite 行为照旧。
- [x] 部署文档分别说明 SQLite 和 PostgreSQL，列出 `pg_dump`、gzip、age、30 天清理和恢复命令。
- [x] 设置页及格式文档说明第 5 版数据包包含的内容、对话按角色编号导入的条件，以及记忆和档案可以继续导入。
- [x] 串行跑完指定后端、前端和受影响测试，完成两路代码审查并清理临时资源。

## Comments

### 实现说明（票 03）

- 去掉启动时加载全站角色的逻辑。对话回合、通话、记忆和标题从 `CharacterRepository` 读取当前账号的角色。生日提示只读同账号角色的名字和生日。后台看板只读活动涉及的角色名，角色删除后保留历史次数，不再显示该角色名。旧测试的额外角色属性只在对应账号的角色行存在时补入。
- PostgreSQL 下备份请求在接触存储桶或备份文件前返回中文说明。后台接口给看板提供 `unavailable_reason`，卡片以普通文字显示；SQLite 继续使用原流程。部署文档中的 PostgreSQL 恢复示例将备份导入新空库，再切换部署的连接。
- 更新设置页和格式文档，说明第 5 版数据包及角色编号不同时的导入结果。Chromium 在 390px 和 1280px 下打开了构建版的数据包页和 PostgreSQL 备份看板。
- 规范审查发现删号测试重复，已将角色断言并入原测试。规格审查没有发现遗漏。复跑后端相关测试 325 个、前端全量测试 789 个，Ruff、Pyright、前端类型检查、shadcn 检查和生产构建均通过。`sh scripts/affected-tests.sh 4cf28e2f` 通过（后端 418 个、前端 563 个）。PostgreSQL 备份文档示例通过 Bash 语法检查。
