# M4 公益上线

本阶段的第一张票落实[改造设计](../../docs/ryugi/specs/2026-11-12-saas-byok-design.md)第 2、3、5 节的站点说明和通知-删除流程。

- 使用条款和隐私政策说明私有角色、导入资料、头像外链、用户自带密钥和第三方处理。页脚提供举报和 AGPL 对应源码入口。
- 访客和登录用户都能提交举报。后台按状态查看并记录处理结果，通过现有用户管理执行封禁、解封或删除。
- 举报是独立的处置记录。公开表单只请求定位和处理所需的信息，联系方式可留空。后台把举报中的链接按文本展示。

第二张票落实用户数据包和自助删除。

- SaaS 只提供对话、记忆和档案的导出与导入。旧包继续按原版本校验，照片、周期记录与信不会导入 SaaS。数据包继续使用第 5 版，不迁移好感度或礼物。
- 数据包按当前用户在数据库中拥有的角色读取姓名和匹配对话。角色配置和资料不在包内，导入的对话按角色 ID 匹配。保留单语言和日中双语回复，重复导入不新增数据。
- 用户确认删除后，先挂断通话，再删除服务端账号和关联数据。服务端删除成功后清除当前浏览器中的自带密钥，并退出登录。

第三张票完成邀请注册与部署说明。用相同的登录和后台接口在 SQLite 与 PostgreSQL 上走一遍：新用户必须带有效邀请，过期、用尽或已删除的邀请失效，老用户及名单内管理者照常登录。空库只在未设置名单时允许第一位用户直接登录，以便取得管理者标识。`eidolon doctor` 在限制注册却没有管理者时给出提示。后台创建、列出和删除邀请。

生产 Compose 从本 fork 的代码在部署机上构建应用镜像，默认单进程，可用同机拆分配置接入共享 PostgreSQL。发布前对照设计第 2、3 节查看仓库内容、默认配置和许可证，并在本地准备全年龄 showcase 登记稿。公开仓库、线上源码链接和真实 OAuth、通话由发布者确认，登记由发布者提交。

## Testing Decisions

用 HTTP 接口和真实 SQLite、PostgreSQL 测试举报、限频、管理员访问和账户清除。通话结束用现有测试浏览器观察。条款和举报页面用 Playwright 在本地构建版中走完整流程。

数据包与自助删除走真实 SQLite 和 PostgreSQL 的 HTTP 接口。用独立后端实例交叉进行角色创建和数据包操作，再用本地构建版的 Playwright 走角色、对话、导出、重复导入和删除流程。

邀请注册测试在两种数据库上通过后台邀请接口和 OAuth 回调走完整流程，仅替代外部身份提供方。`eidolon doctor` 通过 CLI 运行。两套生产 Compose 用合成环境变量解析并确认应用镜像来自本地构建。
