## Comments

### 实现说明（票 02）

- `/api/account/data-package` 继续使用第 5 版格式。导出在同一次数据库读取中按当前用户查角色名。导入先读取并转换文件，再在同一次写入中按角色 ID 判断归属、识别已经存在的对话和记忆，并记录导入次数。角色设置和资料不随包传输。旧包的照片、周期记录和信照原格式校验。导入会跳过这些内容和送礼事件。
- 设置页只提供对话、记忆和档案，说明导出文件没有加密，以及导入档案会替换原档案。删号页面先挂断浏览器通话，收到删除成功的响应后才清除该用户在当前浏览器中的自带密钥。服务端也会等待仍在接通的呼叫结束，撤销所有登录会话并清除关联数据。运行记录保留但去掉用户标识。
- 规范审查发现文件转换占用数据库写线程，以及两组删号测试重复验证同一段清理逻辑。转换已移到写入之前，删号清理用例已合并，另保留管理员接口测试。按票审查发现单进程删号会漏掉尚未接通的呼叫。现在取消这些呼叫，并拒绝在删号后才继续处理的请求。新增用例先复现问题，再通过。
- SQLite 和 PostgreSQL 相关测试共 63 项通过，Ruff 和 Pyright 通过。前端 787 项通过，类型检查、shadcn 纪律脚本和生产构建通过。`sh scripts/affected-tests.sh 9f66b18c` 的后端 433 项通过，1 项仅适用于 Windows 而跳过，前端 561 项通过。构建仍有 `LINE Seed JP` 的既有字体提示。
- 本地构建版 Playwright 使用临时 PostgreSQL 和两个独立后端进程。浏览器创建角色、发送单语言消息、下载并恢复三类数据，第二次导入没有新增。另一个进程读到了新建角色名并导回了对话，另一个用户无法导入该对话。浏览器用真实 WebRTC 接通，外部模型和语音使用测试替代服务。确认删号后，连接先关闭，响应成功后清除本地密钥，两处会话均失效。数据库中该用户的关联数据已清除，另一用户的数据仍在。临时服务、数据库、脚本和截图均已清理。
