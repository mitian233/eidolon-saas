## 2. S3 详规：端点与凭据

### 2.1 embedding

- 统一 OpenAI 兼容 `POST {base_url}/embeddings`，请求体 `{model, input[], encoding_format:"float"}`，
  读取 `data[].embedding` 与 `usage.total_tokens`。现有 `SiliconFlowEmbedder`（`embedding.py:103`）
  已是这个形状，改名并去掉提供方语义即可。
- 用户填：base_url、模型名、维度、自己的 key。端点与 key 同属浏览器持有，不落库（约束 4）。
- 维度：用户填的值写进模型标识（沿用 `model@dimensions` 形态），换模型或维度后旧向量不混用。
- `EMBEDDING_PROVIDER` 枚举与 `GeminiEmbedder` 原生分支退场（`config.py:838-896`）。Gemini 用户
  走 OpenRouter 的 `google/gemini-embedding-2` 或直接填 Gemini 的 OpenAI 兼容端点。
- 未配置端点 = 召回与记忆关闭（`assembly.py` 已有缺件降级），行为与上游「没配向量化」一致。

### 2.2 rerank

- 无通用格式：OpenRouter 不提供重排接口（2026-11-12 实测 `/api/v1/rerank*` 均 404）。
- 保留一种格式实现，按 SiliconFlow 的 `/rerank`：`{model, query, documents[], top_n}`，
  返回 `results[].index` 与 `relevance_score`（`rerank.py:87`）。
- 用户填 base_url、模型名、key；未填 = 未配置重排，召回退到「按余弦相似度取前几条」
  （`retrieval.py` 已有降级路径）。
- 阈值表 `KNOWN_THRESHOLDS`（`rerank.py:32`）按模型名校准；未知模型走 `FALLBACK_MODEL` 的阈值。

### 2.3 判断模型（D14）

- 改用用户自带 LLM 发一次小请求（低推理档），沿用判断模型的三个是非题语义。
- 设置里可整体关闭：关闭或未配时好感度停用、通话表情走默认值、召回退到 `recall_story` 工具兜底（D3）。
- 现有 `judge.py` 的输入键（`用户这句话`）与阈值结构（`judge.py:80`）保持不变，只换调用方。

### 2.4 代理与限额

- `Service` 与 `OWN_KEYS_PROXIED`（`config.py:43,68`）增加 `embedding`、`rerank`。
- 走用户 key 的服务不计平台限额（沿用上游免限额密钥语义，`config.py`）。
- 后台不再有平台凭据区块（S4）。

## 3. 验证

- 每个切片结束时 `ruff` / `pyright` / 全量 pytest 全绿。
- S3 的实际验证：一个只带 LLM key + OpenRouter 向量端点的用户完成带记忆、带 `recall_story` 召回的对话；
  换向量模型或维度后重嵌入，旧向量不被检索到。
- S1 的实际验证：两个 api 实例容器共用一个 Postgres 并发服务文字回合，无串数据。
